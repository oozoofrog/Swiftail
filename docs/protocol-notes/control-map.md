# Control Registration and Map Content Layer

## 1. Introduction

- Reference: `tailscale.com` v1.104.6, `CurrentCapabilityVersion = 148`. For the version number and its meaning, see `tailscale.com/tailcfg/tailcfg.go:38` and `tailscale.com/tailcfg/tailcfg.go:198`.
- Authoring model: GPT-6.1 Sol. Verification: Claude Opus 5.5, 2026-11-14, 16 corrections. The JSON shapes were verified by directly marshaling and unmarshaling the reference module's tailcfg types with Go 1.27.3 `encoding/json`.
- The **implementation proposals** and **test cases** below are proposals for Swiftail. The remaining behavior descriptions report observations from the reference sources cited in each row or sentence.

## 2. Scope

This note covers registration JSON, login state, map requests and responses, frames, incremental state reconstruction, auxiliary calls, and the test server. Its scope is the content layer that POSTs JSON to `/machine/register` and `/machine/map`. (`tailscale.com/tailcfg/tailcfg.go:1313`, `tailscale.com/tailcfg/tailcfg.go:1427`)

This note assumes an existing HTTP/2 connection over Noise. The Noise handshake, HTTP upgrade, HTTP/2 implementation, and details of how load balancer headers are sent are covered in `control-transport.md`. The reference client uses the Noise client for registration and map requests. (`tailscale.com/control/controlclient/direct.go:805`, `tailscale.com/control/controlclient/direct.go:1162`)

In the type tables, `?` denotes a nullable or omittable value, `[]` denotes a JSON array, and `{string: T}` denotes a JSON object. Integer IDs are based on `int64`. Older IDs can exceed `2^53-1`, so Swift must preserve them without converting through floating point. `StableNodeID` and `StableTailnetID` are opaque strings. (`tailscale.com/tailcfg/tailcfg.go:202`, `tailscale.com/tailcfg/tailcfg.go:230`, `tailscale.com/tailcfg/tailcfg.go:249`, `tailscale.com/tailcfg/tailcfg.go:265`)

Public keys are represented as JSON strings with a type prefix followed by hex. `NodePublic` uses `nodekey:`, `DiscoPublic` uses `discokey:`, `MachinePublic` uses `mkey:`, and `NLPublic` uses `nlpub:`. The raw length of `NodePublic` and `DiscoPublic` is 32 bytes. The short key representation for logging is excluded from transmission. (`tailscale.com/types/key/node.go:31`, `tailscale.com/types/key/node.go:331`, `tailscale.com/types/key/disco.go:18`, `tailscale.com/types/key/disco.go:187`, `tailscale.com/types/key/machine.go:26`, `tailscale.com/types/key/machine.go:251`, `tailscale.com/types/key/nl.go:140`, `tailscale.com/types/key/util.go:56`)

Treat `time.Time` as a Go JSON time string and `netip.Addr`, `Prefix`, and `AddrPort` as IP, CIDR, and IP:port strings, respectively. The same module's JSON size calculations also show RFC3339 time strings and bracketed IPv6:port strings. Treat `[]byte` and `MarshaledSignature` as standard base64 strings. Comments in the module's test server also specify that `encoding/json` decodes `[]byte` with `base64.StdEncoding`. The type tables include the Go types passed to JSON marshal/unmarshal. The standard library encoder itself is outside the specified module. (`tailscale.com/tailcfg/tailcfg.go:388`, `tailscale.com/tailcfg/tailcfg.go:395`, `tailscale.com/tailcfg/tailcfg.go:404`, `tailscale.com/types/netlogtype/netlogtype.go:37`, `tailscale.com/types/netlogtype/netlogtype.go:50`, `tailscale.com/types/tkatype/tkatype.go:21`, `tailscale.com/tstest/natlab/vnet/fake_acme.go:480`, `tailscale.com/control/controlclient/direct.go:1447`, `tailscale.com/control/controlclient/direct.go:1523`)

In JSON, `opt.Bool` is `true`, `false`, or `null`, with unset distinct from explicit false. It sends neither the string `"true"` nor `"false"`. Update state only when `Get()` returns a value. Unmarshaling the string `"true"` itself fails (verified by execution), and `null` decodes as explicitly unset. (`tailscale.com/types/opt/bool.go:49`, `tailscale.com/types/opt/bool.go:110`, `tailscale.com/types/opt/bool.go:122`)

JSON details verified by execution with Go 1.27.3 `encoding/json` and the reference module's types:

- Untagged fields are sent even when zero. This applies to `RegisterRequest` fields `NodeKey`, `OldNodeKey`, `NLKey`, `Expiry`, `Followup`, `Hostinfo`, and `NodeKeySignature`, `MapRequest` fields `NodeKey`, `DiscoKey`, and `Hostinfo`, and `Node` fields `ID`, `StableID`, `Name`, `User`, `Key`, and `Addresses`. A zero public key is emitted as its prefix followed by 64 hex `0` digits (`nodekey:000…0`). A zero `time.Time` is emitted as `"0001-01-01T00:00:00Z"`, and nil pointers and slices are emitted as `null`. (`tailscale.com/tailcfg/tailcfg.go:1318`, `tailscale.com/tailcfg/tailcfg.go:1436`, `tailscale.com/tailcfg/tailcfg.go:370`)
- Key text decoding requires an exact prefix match and a hex length of exactly twice the raw length. An empty string is an error. The encoder emits lowercase hex. (`tailscale.com/types/key/util.go:56`, `tailscale.com/types/key/util.go:70`)
- `time.Time` can include fractional seconds (trailing 0s removed, up to 9 digits) and a non-UTC offset in RFC 3339, for example `"2026-01-02T03:04:05.123456789+09:00"`. The Go client's logout `Expiry=time.Unix(123,0)` also uses a local time zone offset. The Swift decoder must accept both fractional seconds and offsets. (`tailscale.com/control/controlclient/direct.go:772`)
- Keys in `map[NodeID]…` and `map[DERPRegionID]…` (`PeerSeenChange`, `OnlineChange`, `DERPMap.Regions`, `DERPHomeParams.RegionScore`) are decimal integer strings in JSON, for example `{"OnlineChange":{"5":true}}`. (`tailscale.com/tailcfg/tailcfg.go:2073`, `tailscale.com/tailcfg/derpmap.go:19`)
- `[]byte` and `MarshaledSignature` use standard base64 with padding, for example bytes `01 02 03` → `"AQID"`.
- A `NodeCapMap` value is `null` for a nil slice, for example `"CapMap":{"cap/x":null}`. The decoder must accept both `null` and `[]` as "no arguments." (`tailscale.com/tailcfg/tailcfg.go:486`, `tailscale.com/control/controlclient/map.go:194`)

### 3.5 Compression, Size, and KeepAlive

Both the schema and server support interpreting `Compress=""` as uncompressed. testcontrol compresses with zstd only when `req.Compress != ""` and puts the JSON bytes directly into the frame for an empty value. As a test server simplification, it skips checking for `"zstd"`, so any nonempty string enables compression. (`tailscale.com/tailcfg/tailcfg.go:1444`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:1526`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:1918`)

The client-side findings are narrower. The reference Go client **always** sets `Compress="zstd"`, and the decoder decodes every frame as zstd. An uncompressed receive path in this version of the Go client is therefore unverified. To use an empty Compress, the Swift decoder must select its own uncompressed JSON branch. (`tailscale.com/control/controlclient/direct.go:1139`, `tailscale.com/control/controlclient/direct.go:1488`)

Compression operates on one frame at a time. Go treats each frame's N bytes as an independent, complete zstd frame (RFC 8878) and decodes it in one operation (`DecodeAll`), with no compression dictionary or stream context carried between frames. testcontrol also calls `AppendEncode` separately for each message. Swift can therefore start a new zstd decode per frame, but the all-Swift policy requires implementing a zstd decoder directly or verifying that the production server honors `Compress=""` (§8). (`tailscale.com/control/controlclient/direct.go:1496`, `tailscale.com/util/zstdframe/zstd.go:69`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:1927`)

Read exactly 4 bytes for the frame prefix and accumulate exactly N bytes after it. HTTP/2 DATA boundaries do not define map message boundaries. Fail before allocation if N exceeds `256<<20`, and cap the zstd decompressed size at `1<<30`. The stream body has no total size limit because the number of messages is unlimited. Noise response bodies outside map streaming (registration responses and non-200 map error bodies) are limited to `1<<20` bytes. (`tailscale.com/control/controlclient/direct.go:1157`, `tailscale.com/control/controlclient/direct.go:1208`, `tailscale.com/control/controlclient/direct.go:1439`, `tailscale.com/util/httpbody/httpbody.go:34`, `tailscale.com/control/controlclient/direct.go:1454`, `tailscale.com/control/controlclient/direct.go:1471`)

`KeepAlive=true` carries no netmap delta. The schema specifies that only `PingRequest`, `ControlTime`, and `PopBrowserURL` are also valid. Direct actually handles `ClientVersion` and `ControlDialPlan` as well before the KeepAlive branch. Account for this observed difference in the implementation. KeepAlive leaves Node, Peers, and policy unchanged. (`tailscale.com/tailcfg/tailcfg.go:2021`, `tailscale.com/control/controlclient/direct.go:1299`, `tailscale.com/control/controlclient/direct.go:1312`, `tailscale.com/control/controlclient/direct.go:1324`)

End the stream with an error if the first **non-KeepAlive** response lacks Node. Successful netmap synchronization requires more than HTTP 200. Read, zstd, and JSON failures also end the current session. (`tailscale.com/control/controlclient/direct.go:1269`, `tailscale.com/control/controlclient/direct.go:1286`, `tailscale.com/control/controlclient/direct.go:1353`)

## 4. Procedures and State Machine

### 4.1 Registration, Authentication, Authorization, and Key Rotation

1. Prepare the local machine identity and current node key. Go fails if the machine key is zero and creates a new node key if the key is missing or expired or the login is interactive. During key rotation it saves the previous private node key separately to populate `OldNodeKey`. (`tailscale.com/control/controlclient/direct.go:649`, `tailscale.com/control/controlclient/direct.go:657`, `tailscale.com/control/controlclient/direct.go:704`)
2. For auth key login, register with `Auth={AuthKey: …}`. Without an auth key, omit Auth and follow the registration response's AuthURL branch. Go splits a wrapped auth key containing `--TL` into the AuthKey before `--TL` and lock signing material. It sends only the first part as `Auth.AuthKey` and builds `NodeKeySignature` with the material. Without `--TL`, send the full key string as-is. Do not send the entire wrapped key as AuthKey even if Swift lacks lock support. (`tailscale.com/tka/sig.go:467`, `tailscale.com/control/controlclient/direct.go:643`, `tailscale.com/control/controlclient/direct.go:739`, `tailscale.com/control/controlclient/direct.go:779`)
3. Even after HTTP 200, branch in the order `Error`→`NodeKeySignature`→`NodeKeyExpired`. Error means failure, a returned signature means re-sign and re-register, and NodeKeyExpired means retry once with a new key. If the key has already been regenerated and is again expired, return an error. (`tailscale.com/control/controlclient/direct.go:534`, `tailscale.com/control/controlclient/direct.go:854`)
4. If there is an AuthURL, give it to the user and send a registration POST with `Followup=AuthURL` using the **same candidate NodeKey**. Followup is a long poll. Replace the AuthURL if it is new, and back off if the same URL repeats immediately. Wait for authentication before committing the candidate as the current key. (`tailscale.com/control/controlclient/direct.go:526`, `tailscale.com/control/controlclient/direct.go:708`, `tailscale.com/control/controlclient/direct.go:888`, `tailscale.com/control/controlclient/auto.go:359`, `tailscale.com/control/controlclient/auto.go:376`)
5. If AuthURL is empty, Go commits the candidate as the current private node key and starts the map after successful login. This function uses no failure branch for `RegisterResponse.MachineAuthorized`. Authentication success and device authorization are therefore separate states. (`tailscale.com/control/controlclient/direct.go:888`, `tailscale.com/control/controlclient/auto.go:410`, `tailscale.com/control/controlclient/auto.go:428`)
6. If the map self Node has `MachineAuthorized=false`, stay in `NeedsMachineAuth` and keep the stream open while awaiting approval. testcontrol sets the field to true with `CompleteDeviceApproval` and signals that the self node needs an update. Once true, the Go backend transitions to Starting. (`tailscale.com/types/netmap/netmap.go:199`, `tailscale.com/ipn/ipnlocal/local.go:7080`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:950`)
7. When the local node's `KeyExpiry` passes, the Go backend transitions to NeedsLogin. The next registration takes the expired key rotation path. For peers, preserve `Expired` and account for the `ControlTime` clock offset when calculating expiration. A comment notes that removing Endpoints alone is insufficient to sever communication. (`tailscale.com/ipn/ipnlocal/local.go:1924`, `tailscale.com/ipn/ipnlocal/local.go:7076`, `tailscale.com/control/controlclient/direct.go:646`, `tailscale.com/ipn/ipnlocal/expiry.go:63`, `tailscale.com/ipn/ipnlocal/expiry.go:100`)
8. Log out by registering with the current NodeKey and an `Expiry` in the past, through the registration path rather than a separate `/logout` path. Go uses `time.Unix(123,0)` and clears persist after the registration attempt. On success, Auto ends the login state and map/auth work. (`tailscale.com/tailcfg/tailcfg.go:1332`, `tailscale.com/control/controlclient/direct.go:505`, `tailscale.com/control/controlclient/direct.go:706`, `tailscale.com/control/controlclient/direct.go:771`, `tailscale.com/control/controlclient/auto.go:856`)

Ephemeral is a server-side lifetime policy request in registration. The reference testcontrol registration handler has no branch for Ephemeral automatic deletion or for storing Expiry, so it cannot verify production ephemeral GC or logout deletion. (`tailscale.com/tailcfg/tailcfg.go:1340`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:973`)

### 4.2 Starting, Updating, and Reconnecting the Map

1. Separate state upload from receiving after registration completes. **Implementation proposal:** First upload Hostinfo, NetInfo, DiscoKey, and Endpoints with `Stream=false, OmitPeers=true, ReadOnly=false` and check for HTTP 200. Then start receiving with `Stream=true, OmitPeers=false, KeepAlive=true`. This ordering is a Swiftail proposal for deterministic initial state. Go Auto schedules both jobs in restartMap after login, with no guaranteed order of completion. (`tailscale.com/tailcfg/tailcfg.go:1466`, `tailscale.com/tailcfg/tailcfg.go:1518`, `tailscale.com/control/controlclient/auto.go:303`, `tailscale.com/control/controlclient/auto.go:428`)
2. For streaming requests at Version>=68, do not rely on sending Hostinfo or other state update values. testcontrol ignores Hostinfo, Endpoints, DiscoKey, and similar fields altogether. Send changes to UDP addresses, DiscoKey, Hostinfo, NetInfo, and TKAHead separately as non-streaming updates. (`tailscale.com/tailcfg/tailcfg.go:1466`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:1452`, `tailscale.com/control/controlclient/auto.go:259`, `tailscale.com/control/controlclient/auto.go:681`, `tailscale.com/control/controlclient/auto.go:706`, `tailscale.com/control/controlclient/auto.go:888`)
3. Check only the HTTP status of an update request and drain and discard the response. The server may omit the body entirely, so do not require a map frame. Update requests can run in parallel with reading a session. (`tailscale.com/tailcfg/tailcfg.go:1518`, `tailscale.com/control/controlclient/direct.go:1223`, `tailscale.com/control/controlclient/direct.go:971`)
4. Create the session state after receiving Node in the initial non-KeepAlive, and apply later frames in order. Map state belongs to this stream. Reconnect on EOF, timeout, or decoding errors. A minimal client without resumption starts state over from a new full map. Go Direct likewise creates a new mapSession for each request and leaves MapSessionHandle/Seq unset. (`tailscale.com/control/controlclient/direct.go:1092`, `tailscale.com/control/controlclient/direct.go:1228`, `tailscale.com/control/controlclient/direct.go:1269`, `tailscale.com/control/controlclient/direct.go:1353`)
5. Track the generation number of the latest local state and mark only successful generations complete. On failure, keep the current stream open and retry the update itself after backoff. (`tailscale.com/control/controlclient/auto.go:59`, `tailscale.com/control/controlclient/auto.go:90`)

### 4.3 mapSession Delta Application Algorithm

1. Process allowed auxiliary KeepAlive events first and skip netmap updates. For ordinary messages, handle Debug actions first. (`tailscale.com/control/controlclient/direct.go:1299`, `tailscale.com/control/controlclient/direct.go:1332`, `tailscale.com/control/controlclient/map.go:167`)
2. Normalize self and new or changed peers. If HomeDERP is 0 and legacy `DERP` is `127.3.3.40:N`, move N to HomeDERP. If AllowedIPs is nil, copy Addresses. If UnsignedPeerAPIOnly is set, remove AllowedIPs other than the node's own Addresses. Add keys from self's old Capabilities that are missing from CapMap as CapMap entries with no value. (`tailscale.com/control/controlclient/map.go:182`, `tailscale.com/control/controlclient/map.go:244`)
3. Store peers as `NodeID → Node`. If `Peers.count>0`, replace the store with the list and stop processing peer deltas for this message. `Peers=[]` leaves existing peers in place. The store starts empty, so it can represent an initial state of 0 peers, but removing the last existing peer requires PeersRemoved. (`tailscale.com/control/controlclient/map.go:550`)
4. Without a full Peers list, apply `PeersRemoved`→`PeersChanged`→`PeerSeenChange`→`OnlineChange`→`PeersChangedPatch` in that order. Removed deletes and Changed **upserts the entire node**. Seen=false sets LastSeen to nil and leaves the peer in place. Seen=true sets LastSeen to the receiver's current time, and Online stores its value as-is. Both ignore unknown IDs. (`tailscale.com/control/controlclient/map.go:582`)
5. Apply patches only to existing NodeID values. Replace `DERPRegion` and `Cap` when nonzero and `Endpoints`, `KeySignature`, and `CapMap` when non-nil. For `Key`, `DiscoKey`, `Online`, `LastSeen`, and `KeyExpiry`, replace the field with the pointed-to value when the pointer is non-nil. Thus `Endpoints=[]` and `CapMap={}` clear their values, `Online=false` sets offline, and a nil LastSeen patch leaves LastSeen intact (use Seen=false to clear LastSeen). (`tailscale.com/tailcfg/tailcfg.go:3031`, `tailscale.com/control/controlclient/map.go:621`)
6. If a `PeersChanged` node differs from the existing node only in fields representable by patches (Key, KeyExpiry, KeySignature, DiscoKey, Endpoints, HomeDERP, Cap, CapMap, Online, LastSeen), Go turns those differences into a patch and appends it to `PeersChangedPatch` in place of a full replacement (`patchifyPeersChanged`). With no differences, it discards the entry. Most responses yield the same result as full replacement, but the two are **not equivalent**. Patches apply last and only to peers still present, so if one response removes a peer with `PeersRemoved` while changing it with `PeersChanged`, any change converted to a patch is lost (removal wins). The peer is restored only if other fields changed. This was verified with data extracted from Go's actual mapSession (`peer-upsert-remove` in `Tests/SwiftailControlTests/Fixtures/map-sessions.json`). Swift follows the same rule. Sort by Node.ID when exposing the store externally. (`tailscale.com/control/controlclient/map.go:210`, `tailscale.com/control/controlclient/map.go:694-720`, `tailscale.com/control/controlclient/map.go:758`)
7. If self Node is present, replace the entire object and rebuild the capability set. UserProfiles are upserted by ID without deletion. Select netmap profiles from the preserved profiles for self.User, peer.User, and peer.Sharer. (`tailscale.com/control/controlclient/map.go:371`, `tailscale.com/control/controlclient/map.go:384`, `tailscale.com/control/controlclient/map.go:674`, `tailscale.com/control/controlclient/map.go:1054`)
8. DERPMap=nil preserves the map. Remove regions whose value is nil in non-nil Regions. If the previous DERPMap exists and new Regions=nil, preserve the old Regions **and OmitDefaultRegions**. Regions={} clears the entire region list. HomeParams=nil preserves the previous object. When HomeParams is present and RegionScore=nil, preserve only the previous scores. An empty RegionScore={} resets scores. Do not assume patches by region ID. (`tailscale.com/control/controlclient/map.go:389`, `tailscale.com/tailcfg/derpmap.go:63`)
9. If PacketFilter is non-nil, first replace only the named filter `base`. If PacketFilters contains `"*":null`, clear all existing names **including that base**. For the remaining names, replace non-nil values and delete null values. The final rules concatenate the arrays after sorting by name. An empty base alone leaves rules under other names intact. (`tailscale.com/tailcfg/tailcfg.go:2114`, `tailscale.com/control/controlclient/map.go:447`)
10. Replace the entire DNSConfig, SSHPolicy, or TKAInfo object when non-nil. Apply only a set CollectServices bool and replace Domain and DomainDataPlaneAuditLogID only when nonempty. Replace the entire Health array when non-nil, and apply DisplayMessages upserts and deletions by ID after processing a `*` reset, if present. (`tailscale.com/control/controlclient/map.go:482`)
11. Generating a full netmap from reconstructed state is interoperable. Reproducing Go's internal delta optimization API is unnecessary. That optimization also regenerates a full netmap from reconstructed state for changes it cannot handle. (`tailscale.com/control/controlclient/map.go:212`, `tailscale.com/control/controlclient/map.go:1004`)

PacketFilter data consists of `FilterRule.SrcIPs` string[] and optional `SrcBits` int[], `DstPorts` NetPortRange[], `IPProto` int[], and `CapGrant` CapGrant[]. SrcIPs accepts IP, `*`, CIDR, range, and `cap:` forms. Empty IPProto means TCP/UDP/ICMP. DstPorts and CapGrant are mutually exclusive. The former grants network access and the latter grants WhoIs application rights. `NetPortRange` has `IP` string, the old `Bits` int?, and `Ports={First:uint16,Last:uint16}`. CapGrant has `Dsts` CIDR[], the old `Caps` string[], and `CapMap`={cap:string → array of raw JSON values}. (`tailscale.com/tailcfg/tailcfg.go:1550`, `tailscale.com/tailcfg/tailcfg.go:1572`, `tailscale.com/tailcfg/tailcfg.go:1580`, `tailscale.com/tailcfg/tailcfg.go:1714`)

### 4.6 Tailnet Lock and Capability Selection

The TKAInfo `Head` string is the latest AUM hash, and the `Disabled` bool signals intent to disable. A different head requires a separate synchronization RPC. Keep the local lock when Disabled=true is the only evidence. Go gets and verifies the disablement secret through bootstrap, and a delta with TKAInfo=nil preserves the current state. (`tailscale.com/tailcfg/tka.go:85`, `tailscale.com/tailcfg/tailcfg.go:2179`, `tailscale.com/ipn/ipnlocal/tailnet-lock.go:340`)

**Implementation proposal:** If M2 is limited to tailnets with lock disabled, defer `TKAHead`, signatures, and AUM synchronization. This assumes no locally trusted lock state and no active server TKA. If lock is ignored on an enabled tailnet, Go peers remove the unsigned Swift node from their netmap, and skipping verification on the Swift side fails to uphold the security semantics of lock. Do not use the `UnsignedPeerAPIOnly` exception to bypass restrictions on general traffic. (`tailscale.com/control/controlclient/map.go:1039`, `tailscale.com/ipn/ipnlocal/tailnet-lock.go:185`, `tailscale.com/tailcfg/tailcfg.go:488`)

Whether the production server always permits omission of NLKey itself is unverified. The reference Go client always generates an NL key, uses a wrapped auth key to make an additional lock signature, and uses the NL key to re-sign the NodeKeySignature returned during rotation. For a minimal client, lack of lock support and skipping NLKey generation are therefore separate decisions. (`tailscale.com/control/controlclient/direct.go:721`, `tailscale.com/control/controlclient/direct.go:734`, `tailscale.com/control/controlclient/direct.go:759`)

148 is a cumulative capability level rather than a single feature bit. Advertising 148 signals that the client understands the semantics in that version history. ## 6. Swiftail Minimum Scope and Deferred Work

### 6.1 Implementation Proposal for the M2 Gate

1. Implement registration JSON models, public key text, and current, candidate, and previous node key state. First pass testcontrol login without authentication and with RequireAuthKey. Keep separate branches for Error on HTTP 200, AuthURL, and expiration. (`tailscale.com/tstest/integration/testcontrol/testcontrol.go:995`, `tailscale.com/control/controlclient/direct.go:854`)
2. Separate lite updates carrying Hostinfo from map streaming. Explicitly fix the request Version in tests. For simplicity, choose one mode first, uncompressed or zstd, and match the decoder to the request Compress. (`tailscale.com/tailcfg/tailcfg.go:1444`, `tailscale.com/tailcfg/tailcfg.go:1466`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:1526`)
3. Implement 4-byte LE framing, size limits, exact-length accumulated reads, KeepAlive, the watchdog, and EOF reconnection. Manage netmap as self, a NodeID dictionary, and preserved profile, policy, DNS, and DERP state, and require an initial Node. (`tailscale.com/control/controlclient/direct.go:1169`, `tailscale.com/control/controlclient/direct.go:1353`, `tailscale.com/control/controlclient/direct.go:1471`, `tailscale.com/control/controlclient/map.go:82`)
4. Implement both full Peers and PeersChanged/PeersRemoved. Then add patches, Seen, Online, policy, and partial DERP updates using the algorithm in this note. While 148 is advertised, the production server may send these deltas, so apply them all before the real tailnet gate. Ignoring them leaves stale peer keys, endpoints, home DERP, online state, and filters. testcontrol does not generate deltas automatically, so its tests cannot expose these omissions. The M2 acceptance test injects raw deltas to verify removal through the last peer. (`tailscale.com/control/controlclient/map.go:550`, `tailscale.com/tstest/integration/testcontrol/testcontrol.go:328`)
5. Keep pending authorization and expired states out of Ready. Implement basic HEAD PingRequest, rate-limit waiting, and ordinary backoff. The proposed policy explicitly marks active lock as unsupported and does not start general traffic. (`tailscale.com/ipn/ipnlocal/local.go:7076`, `tailscale.com/control/controlclient/direct.go:1636`, `tailscale.com/control/controlclient/direct.go:624`, `tailscale.com/ipn/ipnlocal/tailnet-lock.go:185`)

**Conditions for deferral:** If M2 acceptance is limited to registration and netmap reception and the test configuration avoids lock, subnets, exit nodes, SSH, Funnel, remote management, and production posture policies, the proposal defers data-plane WireGuard connections, DERP/STUN measurement, MagicDNS query handling, the public WhoIs API, detailed c2n handler paths, ACME, device attrs, audit logging, and automatic updates. Maps carry data-plane configuration and DNS, among other things. The auxiliary features above have separate handlers and calls, so netmap content can be preserved independently of executing those features. (`tailscale.com/tailcfg/tailcfg.go:1985`, `tailscale.com/control/controlclient/direct.go:1640`, `tailscale.com/control/controlclient/direct.go:1758`, `tailscale.com/control/controlclient/direct.go:1877`, `tailscale.com/ipn/localapi/localapi.go:597`)

This proposal excludes allowing all production traffic without understanding PacketFilter. An empty filter array blocks all traffic, and the contract bars UnsignedPeerAPIOnly nodes from network access. M2 verifies only preservation and delta reconstruction of policy. Enforce policy at the stage when data-plane connectivity starts. (`tailscale.com/tailcfg/tailcfg.go:2100`, `tailscale.com/tailcfg/tailcfg.go:488`)
